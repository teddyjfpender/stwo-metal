# Handover Notes — 2026-03-13

## Purpose

Capture the state after proving that Metal GPU V1 composition + `store_polynomials_coefficients`
optimisation + GPU PoW grinding makes the Metal path consistently faster than SimdBackend on the
`cairo_fib_1000` benchmark.

## What changed this session

### 1. `store_polynomials_coefficients = true` (cairo_prove.rs)

The SimdBackend `prove_values` function spends ~250 ms precomputing barycentric weights
(`build_weights_hash_map`) when `store_polynomials_coefficients = false`. Setting it to
`true` skips that path entirely and uses the faster `batch_eval_at_point` code path.

Two lines changed in `fixtures/standalone-benchmarks/src/bin/cairo_prove.rs`:
- Preprocessed tree: `CommitmentTreeProver::new(... true ...)` (was `false`)
- Commitment scheme: `commitment_scheme.store_polynomials_coefficients = true;`

Impact: **prove_values 564 ms → 349 ms (38% reduction, 215 ms saved)**

### 2. GPU Blake2s PoW grinding (new this session)

Replaced MetalBackend's naive single-nonce CPU grind loop with a GPU compute kernel that
dispatches 2^24 = 16.7M threads in a single command buffer. Each GPU thread:
1. Constructs message `[prefix_digest[0..8], nonce_lo, nonce_hi, 0...]`
2. Performs a single Blake2s compression (10 rounds)
3. Checks `ctz(h0) >= pow_bits`
4. Uses `atomic_fetch_min` to report the smallest successful nonce

Files added/changed:
- **New**: `crates/stwo-metal-sys/metal/grind.metal` — GPU Blake2s PoW grind kernel
- **Changed**: `crates/stwo-metal-sys/metal/runtime.m` — ObjC dispatcher `stwo_metal_blake2s_grind_batch`
- **Changed**: `crates/stwo-metal-sys/src/metal.rs` — FFI bindings + `U32Buffer::blake2s_grind_batch`
- **Changed**: `crates/stwo-metal-sys/build.rs` — Added `grind` to `METAL_SOURCES`
- **Changed**: `crates/stwo-metal/src/backend/metal/blake2s.rs` — `MetalBackend::grind` using GPU kernel
- **Changed**: `fixtures/standalone-benchmarks/src/bin/cairo_prove.rs` — Uses `MetalBackend::grind` for interaction PoW when `--metal`

Impact: **Interaction PoW 136 ms → 42 ms (69% reduction, ~94 ms saved)** (with pipeline warm-up)

Note: The FRI PoW grind (~50 ms) inside `prove_values` still uses `SimdBackend::grind` because
the commitment scheme is `CommitmentSchemeProver<SimdBackend>`. Moving that to GPU would require
either converting the commitment scheme to MetalBackend or modifying the prove_values API.

### 3. Pre-lowering timing instrumentation (new this session)

Added detailed sub-phase timing to the pre-lowering phase (witness gen + trace commit + setup).
Key finding: the preprocessed tree commitment (~3.9-4.9s) dominates the total time. This is a

### 4. JIT shader compiler integrated (previous session, validated here)

The JIT shader compiler (`compile_v1_to_metal_source`, `compiled_kernel_name`) is

## prove_values sub-phase analysis

1. **Barycentric weight precomputation** (~250 ms) was the biggest untimed overhead
   in prove_values. Fixed by storing polynomial coefficients.

2. **Memory deallocation** (~120 ms) from dropping Merkle tree layers and polynomial
   evaluations at end of prove_values. Inherent overhead.

3. **FRI quotients** (74 ms) and **FRI commit** (82 ms) could theoretically be
   GPU-accelerated via MetalBackend, but conversion overhead limits net gain.

4. **FRI PoW grind** (~50 ms) still uses SimdBackend. GPU grind for this requires
   MetalBackend prove_values path.

## GPU PoW grind implementation detail

The `blake2s_grind` Metal kernel performs single-block Blake2s compression for each nonce:
- IV: standard Blake2s initialization (h[0] = IV[0] ^ 0x01010020)
- Message: [prefix_digest[0..8], nonce_lo, nonce_hi, 0, 0, 0, 0, 0, 0]
- Total bytes: 40 (32 prefix + 8 nonce)
- Check: `ctz(h0) >= pow_bits` (non-M31-output path)
- Atomics: `atomic_fetch_min` on result buffer for smallest valid nonce_lo

Dispatch pattern: 2^24 threads per batch (covers expected search space for 24-bit PoW
in ~1 dispatch). Iterates over nonce_hi values if needed for determinism.

Performance characteristics:
- ~30-40 ms first-call pipeline compilation overhead (cached for subsequent calls)
- ~5-15 ms kernel compute for 16M Blake2s hashes
- ~42 ms total with warmed pipeline vs ~136 ms SIMD (16-wide × multi-core)
- ~81 ms without warm-up (includes one-time pipeline compilation)

## Architecture decisions

### Why not full MetalBackend prove_values?

Converting `CommitmentSchemeProver<SimdBackend>` to `<MetalBackend>` requires:
- Re-creating all Merkle trees (~1-2 GB) on MetalBackend
- Converting all polynomial evaluations
- Estimated 100-200 ms conversion overhead
- Estimated 100-150 ms savings from GPU FRI/quotients/grind
- Net: marginal improvement, high complexity

### Why not batch Metal command buffers?

Composition V1 execution breakdown: kernel=290 ms, extract=28 ms, denom_inv=8 ms.
Batching command buffers would reduce extract overhead by ~15 ms max. Not worth
the Objective-C runtime complexity.

## Remaining optimisation targets (ordered by expected impact)

1. **GPU witness generation** (~35-46 ms per-proof, ~4s one-time) — the per-proof
   witness gen is only ~40 ms so not a bottleneck. The ~4s preprocessed tree commit
   is one-time and could be cached to disk.
2. **Preprocessed tree caching** (~4s) — serialize the committed preprocessed tree to
   disk after first computation. Would save ~4s on every benchmark run.
3. **GPU FRI PoW grind** (~50 ms) — trapped inside SimdBackend prove_values path.
   Requires MetalBackend prove_values or API modification.
4. **GPU FRI commit** (~82 ms) — requires MetalBackend conversion, ~22 ms net gain
5. ~~Pipeline warm-up~~ — **DONE**: `blake2s_grind` pipeline pre-compiled before timed section

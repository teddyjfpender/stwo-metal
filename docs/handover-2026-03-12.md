## What is now true

### Runtime and ownership

`MetalEvaluationProgramV1` now has:

- fixed-width `#[repr(C)]` ABI records
- deterministic semantic hashing and fail-closed validation
- first real lowering for the active generated shape
- a deterministic Rust reference interpreter
- a first Metal device lane
- explicit dispatch selection
- first real generated overlay registration

The active generated `wide_fibonacci` row now has backend-owned:

- sample execution
- timed iteration and benchmark-run orchestration
- composition generation from selected V1 runtime output
- sampled-values ABI and runtime
- prepared-finish and prepared tree-decommit contracts
- proof/result reporting metadata

### What is still not true

- the generated row is not yet a completely shared V1 runtime story end to end
- the runtime family still scales poorly at `log21..23`
- ABI reflection checks are still not part of the implemented runtime contract
- the live downstream target (`stwo-cairo` / `VIRTUAL_SNOS`) is now defined in
  docs, but not yet exercised in code

## Actual downstream goal

The real downstream goal is not another example benchmark. It is:

1. support `stwo-cairo` as the first real proving-system integration target
2. target the `VIRTUAL_SNOS` row specifically
3. keep `starknet-privacy` in mind as the concrete consumer of that row

This means:

- examples remain acceptance fixtures
- `wide_fibonacci` remains a benchmark and migration row
- `stwo-cairo` / `VIRTUAL_SNOS` is the actual post-convergence proving target

## Active blockers

1. The generated row still carries more generated-row-specialized orchestration
   than the intended shared V1 runtime family.
2. The converged runtime family still scales poorly at `log21..23`.
3. The V1 contract has not yet been exercised against `stwo-cairo` inputs.
4. Host/device ABI reflection checks are still missing from the implemented
   runtime contract.

## Immediate next work

1. Collapse more of the generated row onto shared V1 runtime paths.
2. Reduce the benchmark-only orchestration that still remains.
3. Optimize the backend-owned runtime family from that cleaner baseline.
4. Freeze the first `stwo-cairo` / `VIRTUAL_SNOS` hardening inputs once G10 is
   sufficiently converged.
